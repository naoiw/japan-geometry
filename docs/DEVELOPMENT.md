
# 開発・検証手順

## 環境

Node.js 26・npm、およびWebGL対応ブラウザ。Three.js描画を利用するため、WebGLが使えない環境ではエラーを表示します。

```bash
npm install
npm run dev
npm test
npm run build
npm run build:pages:main
npm run build:pages:develop
```

## 責務分離

- `terrain.ts`：純粋関数。XYZタイル、Web Mercator、24bit DEM復号、位置と標高の相互変換。`DEM_ZOOM=7`、`MESH_SEGMENTS=320` でXY解像度を管理。
- `tiles.ts`：地理院DEMタイル通信（同時最大6件）、ブラウザCanvasによるPNGデコード。
- `TerrainScene.tsx`：WebGLシーン・格子生成・頂点色・カメラ・Raycaster・リソース破棄。
- `terrainGeometry.ts`：0倍時の平面ジオメトリを生成。mesh.scale.y=0によるレイキャスト不能を防ぐ。
- `App.tsx`：操作パネル、取得進捗、エラー、選択地点の表示。
- `styles.css`：PCで左側3D／右側コントロール、スマートフォンでは縦並び。

新しい標高データセットを追加する場合、ズーム範囲、画素の欠損値、CORS、タイルの利用条件を必ず確認してください。DEMGM と DEM5/DEM10 の精細度・対応ズームを混同しないこと。

## 確認項目

1. 標高データが実際に国土地理院から取得され、進捗が完了する。取得不可時はエラーで、架空の標高を表示しない。
2. 日本の島々が周辺の地理と正しい方位で表示される（海側を含む矩形）。
3. 地形をドラッグして富士山周辺へ移動し、倍率0×で完全な平面、1×で等倍、10×で強調表示となることを確認する。DEMズーム7・320×320分割の地形が既存より細かいことを確認する。
4. 0×の平面を含む全倍率で地点をクリックでき、緯度経度とDEM由来の標高が表示される。表示倍率を変更しても標高値は変化しない。
5. 表示は標高カラーのみで、地理院標準地図・OpenStreetMapの地図画像を読み込まない。
6. マウスドラッグ、ホイール、スマホのスワイプ、ピンチ操作ができる。「正面視」は南側から北を見る固定カメラ、「視点をリセット」は初期視点と初期ズームへ復帰し、どちらも倍率を変えない。
7. PC・320px幅モバイルで主要操作が画面外に出ない。
8. CSS/JSの参照が `/japan-geometry/` と `/japan-geometry/develop/` の両方で404にならない。
9. 国土地理院の標高タイルの出典表示がユーザーの目に見える位置にあり、フッター右下のGitHubリンクがリポジトリに遷移する。
10. ブラウザコンソールにCORSやWebGLエラーがなく、標高タイル144枚を最大同時6件で取得できる。
11. スマートフォンの読み込み時間と操作時のフレームレートを確認し、性能劣化があればメッシュ数を調整する。

## 今後の拡張例

- DEM10B/DEM5 系の高精細タイルを現在のカメラ範囲でだけ追加ロードするLOD方式。
- 海岸線・国境を正確に切り抜くPolygonマスク。
- 等高線、山名、登山ルート、視点共有URL、スクリーンショット。
- 地形のズームに応じた必要タイルのみの取得とキャッシュ制御。

CIでは計算の単体テストと型チェック・Viteビルドを検証します。実機のWebGL・タイル配信については手動確認が必要です。
